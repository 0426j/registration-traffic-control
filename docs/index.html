2. 시스템 구조도

App 인스턴스는 회차 조회는 Redis 캐시, 접수 확정은 Postgres 트랜잭션, 폭주 구간만 큐를 거쳐 Consumer Worker가 순차 반영. Mock 결제 서버는 별도 프로세스로 지연·실패를 인위적으로 주입.

4. 기술스택 및 스택 관계도

Layer 0(Nginx)가 요청을 받아 Layer 1(Spring Boot App / Consumer Worker)로 분산하고, Layer 1은 Layer 2(PostgreSQL·Redis)에 트랜잭션/락을 걸며 필요 시 대기열을 소비한다. 결제는 외부 Mock 서버 왕복, 지표는 Prometheus가 App에서 긁어가 Grafana로 시각화. 배포는 GitHub Actions CI/CD가 이 전체 Compose 스택을 EC2로 올리는 구조.

5. 실서비스 수준으로 확장할 경우 — 변경사항과 비용

"목만 만들지 말고 실제 상황 기준으로도 보여주자"는 방향에 대한 답. 항목별로 무엇이 바뀌고 비용이 어떻게 드는지 정리.

바뀌어야 하는 것

  • 결제: Mock → 실제 PG 테스트(샌드박스) 연동으로 교체. 토스페이먼츠/포트원(前 아임포트)은 사업자등록 없이도 테스트 API 키로 실제 승인 흐름(요청→콜백→웹훅)까지 그대로 호출 가능 — 무료. 실매출이 발생하는 라이브 연동은 사업자등록+PG 심사가 필요해 포트폴리오 단계에선 제외.
  • 본인인증: PASS/IPIN류는 기업 계약형(월 이용료+건당 과금)이라 포트폴리오 단계에서 비용 대비 실익이 낮음 — Mock 유지 또는 카카오/네이버 소셜로그인으로 대체 권장.
  • 인프라: 로컬 Docker Compose(진짜 분산이 아님) → AWS EC2 위에서 같은 Docker Compose 스택을 그대로 실행. ALB 대신 이미 설계에 있는 Nginx를 LB로 그대로 사용, RDS·ElastiCache·MSK 같은 관리형 서비스는 안 쓰고 Postgres·Redis 전부 EC2 안에 컨테이너로 직접 실행 — 관리형 서비스의 상시 과금 자체를 없앰.
  • 도메인/HTTPS: 포트폴리오 단계에선 도메인 구매·HTTPS 생략, EC2 기본 제공 퍼블릭 DNS/IP로 데모. 나중에 실제로 필요해지면 그때 도메인(연 1~2만원)+무료 인증서(ACM/Let's Encrypt) 추가.
  • 부하테스트 실행 위치: 개발 중엔 로컬 PC에서 k6 실행(무료). 최종 데모 수치를 뽑을 때만 별도 인스턴스를 잠깐 띄워 네트워크 왕복을 포함한 부하를 쏨.
  • CI/CD: GitHub Actions → 빌드 → ECR(or 레지스트리) → EC2 배포까지 자동화하면 "실전 배포" 스토리가 완성됨.

비용 방어 안전장치 (알람이 아니라 실제로 못 나가게 막는 방식)

  • ① 선불/저잔액 카드로 결제수단 등록 — 메인 카드 대신 이 프로젝트 전용으로 잔액이 적은 선불·체크카드를 등록. 카드 잔액 이상은 물리적으로 청구가 안 되므로, 알람을 놓쳐도 손해가 카드 잔액으로 상한선이 잡힘. 세 안전장치 중 가장 근본적인 방어선.
  • ② AWS Budgets Actions (자동조치) — 이메일만 오는 일반 Billing Alarm과 달리, 임계값(예: 3천원) 초과 시 IAM 정책을 자동 부착해 리소스 생성을 차단하거나 지정 EC2를 자동 stop. 사람이 확인 안 해도 동작.
  • ③ 매일 자동 종료 스케줄 — EventBridge로 매일 정해진 시각에 모든 인스턴스를 강제 stop. "끄는 걸 깜빡함" 자체를 원천 차단, 테스트할 때만 수동으로 다시 켬.
